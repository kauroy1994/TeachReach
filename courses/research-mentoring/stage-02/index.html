CS 696 · Stage 02 of 04

Answer questions with executable models

Turn prose about a workflow into a simulation. Compare the answers you can retrieve from a document with the answers that require executing its rules.

Bring your work from Stage 01 · an evidence table and a versioned mapping.

Module 03

Turn a process description into a what-if tool

Translate a short procedure into a traceable simulator, issue a controlled intervention, and explain which parts of the answer come from source clauses and which come from execution.

Bring one source-to-rule table, the historical trace, and both intervention traces. Ask the mentor to approve the runner’s supported changes for a comparison or name the specific clause-to-code mapping that needs revision.

Module 04

Compare lookup and execution on matched interventions

Design a held-out comparison, score numerical answers separately from scope decisions and cited evidence, and identify a case that needs a reliability check.

Bring one frozen batch-level comparison ledger with case IDs, original arrivals, change cards, historical finishes, both predictions, source IDs and traces. Ask the mentor to accept the grouped comparison as evidence about these two batches or identify a specific evaluation flaw.

Reading for the meeting

SimPy · Shared Resources

Trace the waiting time of one request. Which line of the process description gives the simulator permission to start the next job?

Before you move on

Pass Module 05 the original clauses, four frozen intervention cards, historical finish per batch, hand-checked reference answers, method outputs and station traces. Preserve the original and fault-injected versions separately. The next review can ask whether agreement with a historical run is enough to trust an intervention.
